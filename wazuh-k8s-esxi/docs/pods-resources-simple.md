# Сколько ресурсов и на каком поде — простыми словами

Этот документ объясняет **что крутится где**, **сколько CPU/RAM/диска нужно**, без лишней теории.  
Нагрузка: **до 200 агентов Wazuh**. ОС ВМ: **РЕД ОС 8** или **Astra Linux** (одинаковые цифры ресурсов).

---

## Две разные вещи: ВМ и поды

| Что | Простыми словами |
|-----|------------------|
| **ВМ (виртуальная машина)** | Сервер в ESXi. На нём стоит ОС (РЕД ОС / Astra) и Kubernetes. |
| **Под (pod)** | Контейнер с частью Wazuh внутри Kubernetes. Живёт **на** ВМ-worker. |

**Итого нужно 6 ВМ.** Manager и Dashboard — это **не отдельные серверы**, а поды на двух worker-ВМ.

```
ВМ k8s-cp-01          → только «мозг» Kubernetes (API, etcd)
ВМ k8s-worker-01/02   → здесь живут поды Manager + Dashboard
ВМ k8s-indexer-01/02/03 → здесь живут 3 пода Indexer (база алертов)
```

---

## 1. Сколько заказать ВМ в ESXi

| № | Имя (пример) | Для чего | vCPU | RAM | Диски |
|---|--------------|----------|------|-----|-------|
| 1 | `k8s-cp-01` | Управление кластером | **4** | **8 ГиБ** | 100 ГиБ ОС + 100 ГиБ под контейнеры |
| 2 | `k8s-worker-01` | Manager master + Dashboard | **8** | **16 ГиБ** | 100 ГиБ ОС + 200 ГиБ контейнеры |
| 3 | `k8s-worker-02` | Manager worker | **8** | **16 ГиБ** | 100 ГиБ ОС + 200 ГиБ контейнеры |
| 4 | `k8s-indexer-01` | Indexer pod #0 | **8** | **32 ГиБ** | 100 ОС + 100 контейнеры + **2 ТиБ данные** |
| 5 | `k8s-indexer-02` | Indexer pod #1 | **8** | **32 ГиБ** | то же |
| 6 | `k8s-indexer-03` | Indexer pod #2 | **8** | **32 ГиБ** | то же |

**Сумма по кластеру:** 44 vCPU, 136 ГиБ RAM, ~7.1 ТиБ дисков (+ отдельно **≥ 3 ТиБ** NFS/S3 под архивы).

Indexer-ВМ ставьте на **разные физические хосты ESXi** (anti-affinity), иначе потеря одного хоста уронит всю базу.

## 2. Какие поды и сколько они едят

### Под `wazuh-indexer-0` … `wazuh-indexer-2` (три штуки)

| | |
|--|--|
| **Где живёт** | На своей ВМ `k8s-indexer-0N` (только Indexer, другим подам сюда нельзя) |
| **Зачем** | Хранит и ищет алерты (OpenSearch) |
| **CPU** | просит 4 ядра, потолок 7 |
| **RAM** | просит 24 ГиБ, потолок 30 ГиБ (из них ~16 ГиБ — Java heap) |
| **Диск** | **2 ТиБ** локальный SSD на каждую ВМ |
| **Почему 3** | Одна нода может упасть — данные остаются на двух других (реплика) |

### Под `wazuh-manager-master-0` (один)

| | |
|--|--|
| **Где живёт** | На `k8s-worker-01` (роль `wazuh.role=general`) |
| **Зачем** | Принимает агентов, правила, API, кластер Wazuh |
| **CPU** | просит 2, потолок 4 |
| **RAM** | просит 4 ГиБ, потолок 8 ГиБ |
| **Диск** | PVC **50 ГиБ** (данные) + **10 ГиБ** (конфиг) |
| **Порты для агентов** | 1514 (события), 1515 (регистрация), 55000 (API) |

### Под `wazuh-manager-worker-0` (один)

| | |
|--|--|
| **Где живёт** | На `k8s-worker-02` |
| **Зачем** | Второй узел кластера Manager — разгрузка и запас |
| **CPU / RAM** | как у master: 2–4 CPU, 4–8 ГиБ |
| **Диск** | PVC **50 ГиБ** |

### Под `wazuh-dashboard-…` (один)

| | |
|--|--|
| **Где живёт** | На одном из worker (`general`) |
| **Зачем** | Веб-интерфейс |
| **CPU** | просит 0.5, потолок 2 |
| **RAM** | просит 1 ГиБ, потолок 4 ГиБ |
| **Диск** | не нужен (stateless) |
| **Как открыть** | NodePort **31443** → HTTPS |

## 3. Картинка «кто на ком»

```
┌─ k8s-worker-01 (8 CPU / 16 GiB) ─────────────┐
│  pod: wazuh-manager-master-0   2–4 CPU / 4–8 GiB │
│  pod: wazuh-dashboard          0.5–2 CPU / 1–4 GiB │
└──────────────────────────────────────────────┘

┌─ k8s-worker-02 (8 CPU / 16 GiB) ─────────────┐
│  pod: wazuh-manager-worker-0   2–4 CPU / 4–8 GiB │
└──────────────────────────────────────────────┘

┌─ k8s-indexer-01/02/03 (по 8 CPU / 32 GiB) ───┐
│  pod: wazuh-indexer-N          4–7 CPU / 24–30 GiB │
│  диск данных: 2 ТиБ XFS на каждой ВМ            │
└──────────────────────────────────────────────┘

┌─ k8s-cp-01 (4 CPU / 8 GiB) ──────────────────┐
│  только Kubernetes (подов Wazuh здесь нет)      │
└──────────────────────────────────────────────┘
```

На worker 8/16 хватает: master + dashboard вместе в пике ≈ 6 CPU / 12 ГиБ — остаётся запас ОС и kubelet.

## 4. Откуда цифры по дискам Indexer (коротко)

- 200 агентов × ~100 000 событий/день ≈ **231 событие/сек** в среднем (~924 в пике).
- В день первичных данных ≈ **23 ГиБ**, с репликой ≈ **46 ГиБ**.
- 90 дней онлайн ≈ **5 ТиБ** на весь кластер → по **~1.7 ТиБ на ноду** → заказываем **2 ТиБ**.
- Архив (snapshot) на 90 дней ≈ **1.4 ТиБ** → репозиторий NFS/S3 **не меньше 3 ТиБ**.

Политика: **14 дней** горячий поиск → до **90 дней** warm → snapshot и удаление с дисков Indexer.

Подробные формулы: `docs/architecture.md`.

## 5. РЕД ОС 8 и Astra — одинаковые ресурсы, разный «как ставить»

| | РЕД ОС 8 | Astra Linux |
|--|----------|-------------|
| Тип пакетов | RPM (`dnf`/`yum`) | DEB (`apt`) |
| containerd | обычно **бинарники** с GitHub | пакет apt или бинарники |
| Kubernetes | репозиторий `pkgs.k8s.io` **rpm** | репозиторий `pkgs.k8s.io` **deb** |
| SELinux | по умолчанию **permissive** | нет (или свои MAC Astra) |
| firewalld | скрипт откроет порты | ufw/iptables — по ситуации |
| Ресурсы ВМ/подов | **те же**, что в таблицах выше | **те же** |

На **пустом** сервере (без ПО) скрипты сами ставят curl, lvm2, jq, containerd, kubeadm и т.д.  
См. пошагово: **`docs/os-redos-astra.md`**.

## 6. Порядок включения (одна строка на шаг)

1. Создать 6 ВМ, поставить РЕД ОС 8 **или** Astra, прописать IP в `cluster.env` и `/etc/hosts`.
2. На `k8s-cp-01`: `install-control-plane.sh` → сохранить TOKEN и HASH.
3. На worker-01/02: `install-worker.sh`.
4. На indexer-01/02/03: `install-indexer.sh`.
5. С CP: `label-nodes.sh` → `install-manager.sh` → `install-dashboard.sh` → `setup-archiving.sh`.
6. Пройти `docs/checklist.md`.
